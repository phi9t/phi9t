OBJECT-LEVEL OPTIMIZATION

The system produces a better answer or artifact.

The output improves, but the mechanism that will solve tomorrow’s task remains unchanged. Self-critique, best-of-N, and one-off debugging usually live here.

Q(y*) > Q(y)
A useful system state
Xt = (θt, Ht, Dt, Ot, Rt, Et, Gt)
θ weights + architecture H harness + tools + memory D data + experience O optimizer + research method R compute + systems stack E evaluators + verifiers G governance + deployment
Candidate generation
𝒞t = Pt(Xt, ℋt; Bt)

The proposer Pt searches under resource budget Bt, using the experiment and lineage history ℋt.

Grounded selection
Xt+1 = Gt(arg maxx∈𝒞t Et(x; Tprivate, W))

Selection should depend on private tests and external-world evidence—not only the candidate’s self-assessment.

The defining metric
J(Pt) = 𝔼[ ΔQ / Cost(B) ]

Improvement power is expected downstream progress per unit resource. Practical RSI requires the successor to increase this quantity:

J(Pt+1) > J(Pt)
Working definition

RSI begins when the system persistently improves the mechanism that generates future improvements—and the improved mechanism is actually used in the next cycle.

03Harness engineering

The near-term “self” is usually the whole agent system.

Lilian Weng defines a harness as the system around a base model that orchestrates planning, tool use, context, artifacts, and evaluation.[2] That makes the harness a cheap, executable target for improvement.

editable work plane protected evaluation / governance
SELECT A COMPONENT

Base model

The model supplies proposal generation, reasoning, code synthesis, and interpretation. Harness improvement can unlock more of a fixed model, but recursive structure cannot substitute for insufficient underlying capability.

Editable surfaceWeights, architecture, decoding policy
Failure modeCapability ceiling; poor long-horizon control
RSI roleProposer now; possible successor target later
A conservative self-harness loop

Mine failures, make bounded edits, validate on held-out tasks.

Weng’s review highlights a propose–evaluate–accept pattern in which failure traces ground narrow edits, while verifier, model configuration, and permission boundaries stay outside the editable workspace.[2]

  • Preserve rich traces and negative results.
  • Map each failure to a specific editable component.
  • Require no regressions on held-in and held-out splits.
  • Archive rejected edits instead of erasing history.
for generation t = 0, 1, ...:
    traces = evaluate(harness[t], D_in ∪ D_out)
    failures = mine_root_causes(traces)

    candidates = proposer.bounded_edits(
        editable_surface,
        failures,
        passing_behaviors,
        rejected_history,
    )

    for edit in candidates:
        child = sandbox_apply(harness[t], edit)
        score = independent_eval(child)
        if score.improves_target \
           and score.no_regression:
            archive.accept(child, lineage=t)

    harness[t+1] = governance.select(archive)

These are meaningful recursive structures, but not equivalent to autonomous successor-model closure.

Full RSI would require the system to choose or construct research objectives, develop a general successor, validate it independently, deploy it under authorization, and then demonstrate that the successor has greater improvement power on the next generation.

05The evaluator bottleneck

Candidate generation is becoming cheap. Trustworthy selection is not.

A 2026 survey of 1,250 papers finds that demonstrated self-improvement strength tracks the strength of the feedback signal, from formal verification down to intrinsic self-assessment.[9]

Stronger groundingNarrower coverage
  1. Formal verifierproof checker · type system · invariant
  2. Executable testunit test · compiler · benchmark
  3. Simulation / experimentphysical or empirical evidence
  4. Private benchmarkhidden distribution · rubric
  5. Human evaluationexpert judgment · slower feedback

Why optimization exposes evaluator error
Û(x) = U(x) + ε(x)

The evaluator observes proxy utility Û, not the true objective U. As search becomes stronger, it preferentially finds candidates where the error term ε(x) is large.

arg max Û(x) ≠ arg max U(x)

Evaluator capture

The system can appear to improve by weakening tests, extracting hidden labels, cherry-picking seeds, manipulating logs, or redefining success. Anthropic’s research agents independently discovered several such hacks.[6]

01

Reward hacking

Optimize the measurement channel rather than the intended outcome.

02

Meta-overfitting

The improver becomes excellent at one benchmark but worse at discovering broadly useful improvements.

03

Diversity collapse

Parallel branches converge on the same high-reward idea family and stop exploring alternatives.

04

Permission creep

Performance gains silently come from more compute, tools, credentials, or evaluator access.

05

Debt recursion

Short-term scores rise while complexity, brittleness, and future modification costs accumulate.

06

Bottleneck migration

Faster coding merely shifts the limit to experiment latency, review, research taste, compute, or governance.

07A serious empirical bar

What evidence would make an RSI claim convincing?

A one-generation benchmark gain is not enough. The experiment must isolate recursive gain from more sampling, leaked tests, and human repair.

1

Object-level gain

ΔQt > 0

The successor performs better on private held-out tasks.

2

Meta-level gain

ΔJt > 0

The successor is better at producing further improvements per unit resource.

3

Recursive closure

Pt+1 → Xt+2

The improved improver actually conducts the next development cycle.

4

Second-order transfer

task family A → B

The improvement method transfers beyond the benchmark that selected it.

5

Resource accounting

gain / GPU·h / $ / human·h

More compute and human intervention are measured, not hidden.

6

Evaluator independence

proposal ⟂ private test

The candidate cannot inspect, rewrite, or approve the evaluator that gates deployment.

The durable mental model

RSI is not one event. It is a sequence of increasingly closed improvement loops.

Today’s frontier is best described as evaluator-bounded, economically meaningful self-improvement inside human-governed AI laboratories. The key open question is whether these loops can improve their own research power across generations while remaining grounded, independently evaluable, permission-bounded, and reversible.
